## Терминология

 - Сущность = функция | тип | алиас | переменная (алиас - это всё, что написано через `using`)
 - Шаблон сущности = отрывок кода после template
 - Инстанс = сущность, полученная по шаблону
 - Инстанциация = процесс получения сущности по шаблону

**Замечание:** шаблоны алиасов появились с C++11, а шаблон переменной - с C++14

**Замечание:** _очень важно_ не путать шаблоны и сущности. Компилятор различает эти понятия. Например, при поиске какого-то имени компилятор по-разному обрабатывает шаблоны и уже имеющиеся сущности.

**Замечание:** каждый инстанс - это _отдельная, никак не связанная с остальными сущность_. Если, например, сделать инстанс класса, то он ничего не знает про другие инстансы того же шаблона.

## Специализация шаблонов

Специализация шаблонов работает аналогично перегрузке функций - часто хочется иметь отдельную логику для какого-то особого случая шаблона.

### Полная специализация

Полная специализация - это определение шаблона для полностью известного набора аргументов. Естественно, полная специализация сразу приводит к появлению новой сущности.

**Пример:**
```c++
template <typename T>
class Vector {
    T* ptr;
};

template <>
class Vector<bool> {  // Vector<bool> is entity
    std::byte* ptr;
};
```

**Замечание:** полная специализация есть только у шаблонов классов, переменных и функций

### Частичная специализация

Частичная специализация позволяет выделить частные случаи шаблона, не давая полного набора аргументов. Например, можно требовать конкретной зависимости между аргументами шаблона, или же
сделать часть аргументов полностью известными.

**Пример:**
```c++
#include <iostream>

template <typename T, typename U>
class S {
    static void f() {
        std::cout << "Called S<T, U>::f()" << std::endl;
    }
};

template <typename T, typename U>
class S<T, T*> {
    static void f() {
        std::cout << "Called S<T, T*>::f()" << std::endl;
    }
};

int main() {
    using MyS = S<int, int*>;
    MyS::f();  // calls partial specialization
}
```

**Пример:** не исключается ситуация, когда специализации могут равнозначно использоваться в выражении. В такое ситуации будет ошибка
```c++
template <typename T, typename U>
struct S {};

template <typename T>
struct S<T, int> {};

template <typename U>
struct S<int, U> {};

int main() {
    S<int, int> s;  // CE
}
```

**Замечание:** строго говоря, на частичных специализациях компилятор строит частичный порядок, исходя из которого и выбирается специализация. Как именно? Читать в стандарте **(надо самому найти ссылку)**

**Замечание:** для функций нет частичных специализаций, но полные присутствуют. Это довольно логично, учитывая наличие механизма перегрузки функций

## Шаблоны функций

### Поиск функции

Когда компилятор встречает unqualified-id, ему необходимо понять, а что это такое за имя и что означает. В контексте функций допустимы перегрузки, а потому общий алгоритм достаточно сложный:
 1. Поиск объявлений в коде выше (name lookup)
    - Отбираются имена сущностей
    - Отбираются имена шаблонов и для каждого производится подбор шаблонных аргументов. **Инстанцирования не происходит!** Вместо это компилятор синтезирует объявление, как у сущности-функции
    - По итогу, получаем некоторое изначальное множество кандидатов
 2. Выбор кандидата
    - По виду изначального выражения можно сузить множество кандидатов (число аргументов, как был произведён вызов)
    - Получаем множество подходящих кандидатов
    - Выбираем лучшего из подходящих (если таких несколько, то CE)
 3. Реализация кандидата
    (Я не уверен, насколько у этого места есть подтверждение) этап имеет смысл исключительно для шаблонов: тут должно происходить инстанцирование шаблона и выбор специализации

**Вопрос:** а можно ли проверить как-то на практике порядок, существование этих этапов?

### Перегрузка с шаблонами

Стоит всё же заострить внимание на некоторые ситуации, которые могут происходить в перегрузке, когда есть и сущности, и шаблоны.

**Пример:**
```c++
template <typename T>
void f(T x) {}

void f(int x) {}

int main() {
    int x = 0;
    f(x);  // calls void f(int)
}
```

**Правило:** частное лучше общего. Шаблон в этом смысле позволяет работать с любыми типами, поэтому он "более общий" чем конкретная сущность

**Пример:**
```c++
template <typename T>
void f(T) {}

void f(long long) {}

int main() {
    int x = 0;
    f(x);  // calls void f<int>(int)
}
```

**Правило:** точное соответствие типа лучше любых частных случаев

## Вывод типов параметров шаблона

Компилятор умеет выводить типы шаблона, если они не указаны явно. Сделать он это может только для вызовов, используя типы аргументов как отправную точку.

**Важно:** совершенно не обязательно, что тип, который выведет компилятор в шаблонных параметрах, а также тип под место, где находится какой-то аргумент функции, будет совпадать с типом объекта, который передали как этот аргумент

**Пример:**
```c++
template <typename T>
void f(const T&) {}

int main() {
    int x = 0;
    f(x);  // works, T = int, but compiler started from matching const T& and int...
}
```

**Пример:** компилятор не особо различает типы-ссылки и типы-значения
```c++
#include <iostream>

template <typename T>
void f(T& x) {
    std::cout << 1;
}

template <typename T>
void f(T x) {
    std::cout << 2;
}

int main() {
    int x = 0;
    int& y = x;
    f(y);  // CE
}
```

**Пример:** точное соответствие типов включает в себя и все возможные квалификаторы
```c++
#include <iostream>

template <typename T>
void f(T& x) {
    std::cout << 1;
}

template <typename T>
void f(const T& x) {
    std::cout << 2;
}

int main() {
    int x = 0;
    int& y = x;
    f(y);  // 1
}
```

**Замечание:** последний пример особенно важен в контексте конструкторов. Будьте внимательны, когда делаете шаблон конструктора с аргументом по ссылке и шаблонным конструктором, ведь тогда может выбраться неожидаемый метод.

## Разные шаблонные параметры

### Шаблонные параметры по умолчанию

Абсолютно любой параметр шаблона может иметь некоторое значение по умолчанию.

**Пример:**
```c++
template <typename T = int>
class C {};

int main() {
    C c;  // same as C<int> c;
}
```

**Замечание:** параметру шаблона не обязательно иметь имя, то есть допустимо писать `<typename = int>`

### Нетиповые шаблонные параметры (Non-template template parameters, NTTP)

Помимо типа, аргументом шаблона может быть какое-то значение. Из тех, что имеет смысл обсудить сейчас:
 - Ссылка
 - Целочисленный тип (в том числе вещественные с C++20)
 - Указатель
 - Указатель на член класса (!!!)
 - Объект перечисления (`enum`а)

**Пример:**
```c++
#include <cstddef>

template <typename T, std::size_t N>
class Array {
public:
    // Array's API
private:
    T arr_[N];
};
```

### Шаблонные шаблонные параметры (Template template parameters)

Особенно интересная вещь про шаблоны состоит в том, что они могут принимать другие шаблоны на вход как аргументы

**Пример:**
```c++
#include <vector>

template <typename T>
using Vector = std::vector<T>;

template <typename T, template <typename> typename Container = Vector>
class Stack {
public:
    // Stack's API
private:
    Container<T> elements_;
};
```
