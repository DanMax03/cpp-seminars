## Компиляция C++

Что такое программа? [Программа](https://eel.is/c++draft/basic.link#:translation-unit) - это [translation units](https://eel.is/c++draft/lex.separate#def:translation_unit), связанные друг с другом.

## Linkage

У всех сущностей С++ помимо storage есть понятие linkage. Если по-простому, то это свойство отвечает за то между какими translation unit'ами существует сущность.

Есть 3 разных linkage:
 - No linkage
 - External linkage
 - Internal linkage

### No linkage

Сущность не видна даже в рамках собственного translation unit. Такая сущность, как правило, существует внутри другой

**Пример:**
```cpp
void f() {
    // Everything has no linkage
    int x;
    static int y;
    class C {};
}
```

### External linkage

Сущность видна между всеми translation unit'ами

```cpp
int x;
struct S{};
void f();

struct A {
    static int c;
};
```

### Ключевое слово `extern`

Объявление глобальной переменной в нескольких файлах - это нарушение ODR. Чтобы решить, какое из объявлений главное (то есть определение), все остальные должны быть помечены словом `extern`.

Также функции можно помечать `extern`, но для них слово не имеет эффекта - они по умолчанию имеют external linkage.

#### Strong and weak external linkage

Хоть это не относится к стандарту C++, но external linkage подразделяется на strong и weak. Идея простая: мы, как разработчики библиотеки, хотим предоставить пользователю некоторое стандартное поведение,
которое он может переопределить по своему желанию. Тогда то определение, которое мы собираемся сделать стандартным, будет иметь weak external linkage.

Определение сущности с weak external linkage будет видно во всех translation unit'ах, если нету другого определения этого символа с strong external linkage, который перекроет weak-определение во всех translation unit'ах.

**Пример:** переопределение `operator new`

**Пример:**
```cpp
// lib.cpp
// weak external linkage
__attribute__((weak)) void foo() {

}

void feature() {
    foo();
}

// app.cpp
// strong external linkage => covers the one above
void foo() {

}
```

### Internal linkage

Сущность видна только в рамках собственного translation unit

```cpp
static int x;
static void f();

namespace {
    struct S{};  // since C++11
}
```

### Ключевое слово `inline`

В какие-то древние времена, конечно, `inline` означал прямую подстановку функции в место вызова. Со временем смысл слова перешёл в область linkage: ключевое слово `inline` позволяет написать определение функции/переменной
в нескольких translation unit'ах и не иметь при этом нарушения ODR.

Компилятор гарантирует, что `inline` сущность будет в конечном итоге иметь ровно 1 определение. То есть, взятие адреса в разных translation unit'ах всё равно вернёт один и тот же адрес.

Для чего это нужно? Ну, во-первых действительно позволяет компилятору произвести подстановку кода вместо создания какой-то отдельной сущности (обычно это касается не ODR-use случаев, о чём ниже), а во-вторых даёт компилятору
дорогу к девиртуализации вызовов.

**Важно:** если метод класса определён внутри него, то он по умолчанию является `inline`. Если же определение написано снаружи, нужно явно дописывать `inline`:
```cpp
// c.hpp
struct C {
    void f();
};

inline void C::f() {
    std::cout << "Do something" << std::endl;
}
```

### ODR-use

Неформально, ODR-обращение - это такое обращение, которое требует определения (=> переменной, понятного места в памяти):
 - Взятие адреса
 - Чтение значения не compile-time переменной
 - Вызов функции (тогда происходит ODR-обращение к функции)
