# 18

## Allocator Awareness

### Проблема

Теперь в жизни наших контейнеров появилась новая сущность - аллокаторы. Однако, в процессе жизни аллокатора могут происходить разные вещи, связанные с другими объектами-контейнерами:
 - copy construction
 - copy assignment
 - swap

Что нужно делать с аллокатором во всех вышеперечисленных случаях? Копировать тот, что принадлежит другому контейнеру? А если они не равны? А если аллокатор по-умолчанию не работает (ибо не связан с ресурсом)?

При текущем подходе, каждому контейнеру придётся принимать собственные решения о том, что делать с аллокатором. Проблема очевидна: пользователь ничего не знает и никак не контролирует объект для выделения памяти,
который он же и предоставил.

### Решение

Allocator Aware Container - это соглашения о контейнере, который использует аллокаторы и делает это правильно.

Мы дадим пользователю возможность контролировать поведение контейнера при вышеупомянутых операциях, а именно:
 - По умолчанию, контейнер никак не трогает аллокатор (ни пересоздаёт его, ни присваивает ему какие-то особенные значения)
 - Аллокатор может определить метод `a.select_on_copy_construction()`, возвращающий аллокатор, который надо скопировать при copy construction
 - Аллокатор может определить `using propagate_on_copy_assignment` - это структура либо `std::true_type`, либо `std::false_type`. Если `::value == true`, то тогда (и только тогда) аллокатор копируемого контейнера
 будет скопирован в копирующего.
 - Аллокатор может определить `using propagate_on_swap`, который действует как и в предыдущем случае

**Замечание:** Помимо всего этого, есть `using is_always_equal`. Он существует для того, чтобы прописывать спецификатор `noexcept` для функций и оптимизации ветвлений.

Соответственно, Allocator Aware Container должен пользоваться всеми этими вещами.

**Пример:** примерно так выглядит allocator-awareness у `std::vector`
```cpp
template <typename T, typename Allocator>
class Vector {
    using AllocTraits = std::allocator_traits<Allocator>;

public:
    using allocator_type = Allocator;

    Vector(const Vector& other)
        : size_{other.size_}
        , cap_{other.cap_}
        , alloc_{AllocTraits::select_on_copy_construction(other.alloc_)} {
        arr_ = AllocTraits::allocate(alloc_, cap_);  // if throws, it's okay
        
        ssize_t i = 0;

        try {
            for (; i < size_; ++i) {
                AllocTraits::construct(alloc_, arr_ + i, other[i]);
            }
        }
        catch (...) {
            --i;

            for (; i >= 0; --i) {
                AllocTraits::destroy(alloc_, arr_ + i);
            }

            AllocTraits::deallocate(alloc_, arr_, cap_);

            throw;
        }
    }

    Vector& operator=(const Vector& other) {
        Allocator new_alloc = AllocTraits::propagate_on_copy_assignment::value ? other.alloc_ : alloc_;
        
        T* new_arr = AllocTraits::allocate(new_alloc, other.cap_);  // Okay if throws
        ssize_t i = 0;

        try {
            for (; i < other.size_; ++i) {
                AllocTraits::construct(new_alloc, new_arr + i, other[i]);
            }
        }
        catch (...) {
            --i;

            for (; i >= 0; --i) {
                AllocTraits::destroy(new_alloc, new_arr + i);
            }

            AllocTraits::deallocate(new_alloc, new_arr, other.cap_);
        }

        for (i = 0; i < size_; ++i) {
            AllocTraits::destroy(alloc_, arr_ + i);
        }

        AllocTraits::deallocate(alloc_, arr_, cap_);

        arr_ = new_arr;
        size_ = other.size_;
        cap_ = other.cap_;
        alloc_ = new_alloc;

        return *this;
    }

    void swap(Vector& other) noexcept(AllocTraits::propagate_on_swap::value
                                      || AllocTraits::is_always_equal::value) {
        bool is_fast = AllocTraits::propagate_on_swap::value
                       || AllocTraits::is_always_equal::value
                       || alloc_ == other.alloc_;

        if (is_fast) {
            std::swap(arr_, other.arr_);
            std::swap(size_, other.size_);
            std::swap(cap_, other.cap_);

            if constexpr(AllocTraits::propagate_on_swap::value) {
                std::swap(alloc_, other.alloc_);  // No guarantees, but okay...
            }

            return;
        }

        T* new_arr = AllocTraits::allocate(alloc_, other.cap_);  // Okay if throws
        T* other_new_arr = nullptr;

        try {
            other_new_arr = AllocTraits::allocate(other.alloc_, cap_);
        }
        catch (...) {
            AllocTraits::deallocate(alloc_, new_arr, other.cap_);

            throw;
        }

        ssize_t i = 0;
        ssize_t j = 0;

        try {
            for (; i < other.size_; ++i) {
                AllocTraits::construct(alloc_, new_arr + i, other[i]);
            }

            for (; j < size_; ++j) {
                AllocTraits::construct(other.alloc_, other_new_arr + j, operator[](j));
            }
        }
        catch (...) {
            --i;
            --j;

            for (; i >= 0; --i) {
                AllocTraits::destroy(alloc_, new_arr + i);
            }

            for (; j >= 0; --j) {
                AllocTraits::destroy(other.alloc_, other_new_arr + j);
            }

            AllocTraits::deallocate(alloc_, new_arr, other.cap_);
            AllocTraits::deallocate(other.alloc_, other_new_arr, cap_);

            throw;
        }

        for (i = 0; i < size_; ++i) {
            AllocTraits::destroy(alloc_, arr_ + i);
        }

        AllocTraits::deallocate(alloc_, arr_, cap_);
        arr_ = new_arr;

        for (j = 0; j < other.size_; ++j) {
            AllocTraits::destroy(other.alloc_, other.arr_ + j);
        }

        AllocTraits::deallocate(other.alloc_, other.arr_, other.cap_);
        other_.arr_ = other_new_arr;

        std::swap(size_, other.size_);
        std::swap(cap_, other.cap_);
    }
    
private:
    T* arr_{nullptr};
    size_t size_{0};
    size_t cap_{0};
    [[no_unique_address]] Allocator alloc_;
};
```

**Замечание:** стандарт делает явное указание, что копирование аллокаторов безопасно, но то же самое неверно про аллокаторы, потому что
[этого в стандарте просто нет](https://eel.is/c++draft/allocator.requirements.general#:Cpp17Allocator). Конечно, можно верить, что `swap` для аллокаторов работает *правильно*, но строго говоря никто этого не обещал.

**Fun fact:** операция `swap` для контейнеров должна работать за O(1) и при этом быть `noexcept`. В ситуации, когда `alloc1 != alloc2` и при этом `propagate_on_swap::value == false`,
[стандарт говорит, что это UB](https://eel.is/c++draft/container.requirements.general#container.reqmts-65)

## Inner allocator problem

### Проблема

Теперь мы умеем поддерживать аллокаторы на уровне контейнера, но есть нюанс - значением контейнера может быть другой контейнер!

**Пример:** `std::vector<std::string, MyAlloc>` - память под объекты `std::string` выделена при помощи `MyAlloc`, но внутри `std::string` память под строки выделяется через `operator new`

Казалось бы, можно указать аллокатор и для внутреннего контейнера (в примере выше будет что-то типа `std::vector<std::vector<char, MyAlloc2>, MyAlloc1>`), но зачастую чтобы аллокатор был рабочим, он должен быть привязан
к ресурсу (либо явным образом при конструировании, либо посредством копирования от другого аллокатора). Внешний контейнер не знает, что его элементы - это тоже контейнеры! Поэтому в текущем варианте мы обязаны сами всегда
передавать аллокатор как аргумент конструктора элемента, что очевидно неудобно. А если вложенность контейнеров не уровня 2, а 5? Проконтроллировать вручную передачу аллокаторов в нужных местах - достаточно сложная задача.

Нужно решение, которое позволило бы делать передачу аллокатора автоматически.

### Решение

Так как мы работаем с AllocatorAwareContainer, то любая аллокация/деаллокация и, что более важно, конструирование/уничтожение элементов проходят через аллокатор! Значит, мы можем придумать такой хитрый аллокатор-обёртку,
который бы знал о каждом аллокаторе на каждом из уровней вложенности, и просто передавал бы их самостоятельно в процессе `construct`. Именно этим и занимается `std::scoped_allocator_adaptor`.

Он устроен следующим образом:
 - Это шаблон, который принимает в себя остальные аллокаторы `std::scoped_allocator_adaptor<OuterAlloc, InnerAlloc1, ..., InnerAllocN>`
 - Конструктор такого аллокатора принимает в себя объекты остальных аллокаторов (то бишь `outerAlloc, innerAlloc1, ..., innerAllocN`)
 - На уровне своего контейнера, этот аллокатор пробрасывает вызовы `allocate/deallocate` и `construct/destroy` к `outerAlloc`
 - При этом, когда выполняется операция `construct`, он делает следующее:
   - Если *внутренний тип allocator-aware*, то он будет пытаться передать аллокатор `std::scoped_allocator_adaptor<InnerAlloc1, ..., InnerAllocN>`
     (его возвращает метод `inner_allocator()`) в создаваемый элемент следующим образом:
     - Либо получится вызвать `construct(ptr, std::allocator_arg, inner_allocator(), args...)`
     - Либо получится вызвать `construct(ptr, args..., inner_allocator())`
   - Иначе просто зовём `construct(ptr, args...)`

**Замечание:** а как проверить, что тип является allocator-aware? Более того, он должен быть способным работать с переданным ему аллокатором (конструироваться от него хотя бы). Для этого существует type-trait `std::uses_allocator<C, Allocator>`,
который соответствует `std::true_type` тогда и только тогда, когда `C::allocator_type` может быть конструируем от `Allocator` (и `std::false_type` иначе)

**Пример:**
```cpp
int main() {
    // some code here that creates a1, a2, a3

    template <typename T, typename... Allocs>
    using ScopedVector = std::vector<T, std::scoped_allocator_adaptor<Allocs...>>;

    std::scoped_allocator_adaptor<MyAlloc1, MyAlloc2, MyAlloc3> s_a(a1, a2, a3);

               >
    ScopedVector< ScopedVector< ScopedVector<char, MyAlloc1>
                              , MyAlloc1
                              , MyAlloc2
                              >
                , MyAlloc1
                , MyAlloc2
                , MyAlloc3
                > v(10, s_a);
    
    // Now 3 layers use different properly initialized allocators
}
```

**Пример:** в предыдущем примере на каждом уровне вектору передавался `std::scoped_allocator_adaptor`. Естественно, если так не делать, то всё перестанет работать (потому что на каком-то из уровней появится "чистый" аллокатор)
```cpp
int main() {
    // some code here that creates a1, a2, a3

    std::scoped_allocator_adaptor<MyAlloc1, MyAlloc2, MyAlloc3> s_a(a1, a2, a3);

    std::vector< std::vector< std::vector<char, MyAlloc1>
                            , MyAlloc2  // this makes 0 sense!
                            >
               , std::scoped_allocator_adaptor<MyAlloc1, MyAlloc2, MyAlloc3>
               > v(10, s_a);
}
```
