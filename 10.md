# 10

## Виртуальные функции

### Общая идея

Люди - достаточно ленивые существа. В языках программирования это приводит к тому, что мы часто хотим использовать одни и те же имена переменных и функций, при этом реальные действия за этим должны быть разные. Часто
это выглядит так, что вызываются методы некоторого базового класса, объект которого на самом деле является наследником, и в такой ситуации мы хотим вызвать метод наследника.

**Пример:**
```c++
#include <iostream>

struct Base {
    void show() {
        std::cout << "Base" << std::endl;
    }
};

struct Derived : Base {
    void show() {
        std::cout << "Derived" << std::endl;
    }
};

void foo(Base& b) {
    b->show();  // want "Derived", but it will output "Base"
}

int main() {
    Derived d;
    foo(d);
}
```

Для решения таких задач в C++ существует понятие _виртуальных функций_. Виртуальной функцией может быть только метод класса. Класс, который обладает хотя бы одной виртуальной функцией, называется _полиморфным_.

### Ключевые слова `virtual` и `override`

Чтобы сделать функцию виртуальной, нужно хотя бы один раз в её объявлении внутри класса написать спецификатор `virtual`. Тогда, эта функция будет
считаться виртуальной для этого класса и любого его потомка.

**Пример:**
```c++
#include <iostream>

struct Base {
    virtual void show() {
        std::cout << "Base" << std::endl;
    }
};

struct Derived : Base {
    void show() {  // virtual function override
        std::cout << "Derived" << std::endl;
    }
};

void foo(Base& b) {
    b->show();  // outputs "Derived"
}

int main() {
    Derived d;
    foo(d);
}
```

К сожалению, в C++ с самого начала не предусмотрели возможность явно предупреждать пользователя о неправильной сигнатуре виртуальной функции, если он её перегружает. Позднее это появилось вместе с ключевым словом `override`. Если
оно написано рядом с перегрузкой виртуальной функции, то компилятор удостоверится, что этот метод действительно перегрузил какую-то виртуальную функцию предка.

**Пример:**
```c++
struct Base {
    virtual void foo(float) {}
};

struct Derived : Base {
    void foo(double) override {}  // not an override! CE
};
```

**Замечание:** `virtual` и `override` можно писать одновременно, но смысла в этом нет - лучше оставить только второе. Естественно, задавать виртуальную функцию через `override` нельзя (то есть первый раз объявить функцию нужно всё же с `virtual`)

**Совет:** всегда пишите `override`, если перегружаете функцию. Сэкономит вам часы дебага странных вещей.

### Виртуальный деструктор

Деструктор - такой же метод, как и все остальные. Если метод не помечен виртуальным, то выбор вызываемой реализации будет осуществлен во времени компиляции исходя из типа переменной, а не во времени исполнения исходя из реального объекта под переменной.

**Пример:**
```c++
class Base {
public:
    ~Base() {
        std::cout << "Called ~Base()" << std::endl;
    }
private:
    int x = 0;
};

class Derived : public Base {
public:
    Derived(): arr{new char[10]} {}

    ~Derived() {
        std::cout << "Called ~Derived()" << std::endl;
        delete[] arr;
    }

private:
    char* arr = nullptr;
};

int main() {
    Derived* d_ptr = new Derived;
    Base* b_ptr = d_ptr;
    delete b_ptr;  // outputs only "Called ~Base()", thus we have a memory leak!
}
```

Пометив деструктор базового класса виртуальным, мы гарантируем правильное удаление всех потомков.

**Замечание:** несмотря на то, что у всех классов деструкторы называются по-разному, они как бы один и тот же метод для компилятора. Поэтому пометка `virtual ~Base();` делает `~Derived()` так же виртуальным и всё работает.

### Чисто виртуальные функции

Виртуальные функции часто используют для того, чтобы задавать _интерфейсы_ - набор функций/методов, с которыми может оперировать конечный пользователь. В C#, например, есть отдельная категория данных `Interface`, в то время как в C++ её нет. Вместо этого,
есть _чисто виртуальные функции_ - это виртуальные функции, у которых заведомо нет определения в классе, где они объявлены.

Класс, в котором есть хотя бы одна чисто виртуальная функция (полученная объявлением или наследованием) называется _абстрактным_. Объект абстрактного класса нельзя создать.

**Пример:**
```c++
class Shape {
public:
    virtual double perimeter() = 0;  // pure virtual function declaration
};

class Circle : public Shape {
public:
    Circle(double r) : r_{r} {}

    double perimeter() override {
        return 2 * 3.14159265358979 * r_;
    }

private:
    double r_{0.0};
};
```

#### Чисто виртуальный деструктор

Иногда возникает необходимость сделать класс, который был бы абстрактным, но при этом не содержал каких-либо пользовательских чистых функций. Для этого есть _чисто виртуальный деструктор_. Так как мы хотим, чтобы потомки всё же могли создаваться (даже если они
определят свой деструктор, у нашего абстрактного класса он тоже должен быть, потому что потомки рекурсивно зовут предков), нам нужно предоставить определение для такого деструктора.

**Пример:**
```c++
#include <iostream>

struct Base {
    ~Base() = 0;
};

Base::~Base() {
    std::cout << "Called ~Base()" << std::endl;
}

struct Derived : Base {
    ~Derived() {
        std::cout << "Called ~Derived()" << std::endl;
    }
};

int main() {
    Base b;  // CE
    Derived d;  // OK
}
```
